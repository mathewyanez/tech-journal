# 9/7/2026 Lab2

> **Goal:** Turn a plain Windows Server 2022 box (`ad01`) into a Domain Controller, then get DNS and a workstation (`wks01`) working off of it.

## 📖 Key Terms

| Term                             | What It Actually Means                                                                                                                                                               |
| -------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **DNS**                          | The phonebook of the network. Turns names like `fw01.yourname.local` into IPs like `10.0.5.2` so you don't have to memorize addresses.                                               |
| **Active Directory (AD)**        | Microsoft's system for managing users, computers, and permissions from one central place instead of configuring every machine by hand.                                               |
| **Domain Controller (DC)**       | The server actually running AD. The "boss" machine every other computer checks in with to log in and enforce policy.                                                                 |
| **Forest / Domain**              | A domain (`yourname.local`) is the namespace your AD lives under. A forest is the top-level container that can hold one or more domains. In a lab, one domain equals one forest.     |
| **DSRM Password**                | An emergency "break glass" password used only if AD gets corrupted and needs repair. Separate from your normal admin password.                                                       |
| **Domain Admin vs. Local Admin** | Both are literally named "Administrator," which is the trap. **Local Admin** = full control of one machine only. **Domain Admin** = full control of everything joined to the domain. |
| **Forward Lookup Zone**          | DNS records that answer "what's the IP for this name?" (name → IP)                                                                                                                   |
| **Reverse Lookup Zone**          | The opposite: "what's the name for this IP?" (IP → name). Not automatic, has to be created.                                                                                          |
| **A Record**                     | A DNS entry mapping a hostname to an IPv4 address.                                                                                                                                   |
| **PTR Record**                   | The reverse-lookup counterpart to an A record. Maps an IP back to a hostname.                                                                                                        |
| **.local TLD**                   | Not a "real" top-level domain like `.com` or `.edu`, so Windows warns about it. Fine for an internal lab domain, but a genuine debate topic among sysadmins in production.           |

## 🛠️ Walkthrough

{% stepper %}
{% step %}
### Network the server

Static IP `10.0.5.5`, gateway and DNS pointed at the firewall (`10.0.5.2`), timezone set, computer renamed.

Rename _before_ doing anything else; renaming later causes headaches.
{% endstep %}

{% step %}
### Install the ADDS role

Server Manager → Add Roles and Features → Active Directory Domain Services.

This just installs the software. It doesn't turn the server into a DC yet.
{% endstep %}

{% step %}
### Promote to Domain Controller

The actual "become a DC" step. New forest created (`yourname.local`), DSRM recovery password set, `.local` TLD warning accepted.

After reboot you're logging in as the **Domain Administrator**, not the local one.
{% endstep %}

{% step %}
### DNS flips to self-hosted

After promotion, `ad01`'s own DNS setting changes to `127.0.0.1`.

It now answers its own queries locally and forwards anything it doesn't know upstream to the firewall.
{% endstep %}

{% step %}
### Add DNS records manually

Created an A record for `fw01` so it's reachable by name, then built a reverse lookup zone for `10.0.5.0/24` and generated the matching PTR record so lookups work both directions.
{% endstep %}

{% step %}
### Create named user accounts

Using the shared "Administrator" account long-term is bad practice since it kills accountability. Instead:

* `first.lastname-adm` → added to **Domain Admins**
* `first.lastname` → regular, non-privileged user

From here on, day-to-day work happens as one of these named accounts.
{% endstep %}

{% step %}
### Prep the workstation to join the domain

`wks01`'s DNS pointed at `ad01` (`10.0.5.5`).

Easy to forget, and it will break the domain join, since a client must use the domain's own DNS server to find the DC in the first place.
{% endstep %}

{% step %}
### Join `wks01` to the domain

Renamed, joined to `yourname.local`, authenticated with domain admin credentials, rebooted, then logged back in with the **regular** domain account, not the `-adm` one.

Good practice: don't use elevated credentials for routine logins.
{% endstep %}
{% endstepper %}

## ⚠️ Gotchas

{% hint style="warning" %}
The **local Administrator password** set during Server 2022 install becomes the **Domain Administrator password** once promoted to a DC. Pick something strong, don't lose it.
{% endhint %}

{% hint style="warning" %}
A workstation joining the domain must point its DNS at the domain's own DNS server first, or the join fails outright.
{% endhint %}

{% hint style="warning" %}
Two accounts named "Administrator"—one local and one domain—is a classic source of confusion. Always know which one you're logged in as.
{% endhint %}

{% hint style="warning" %}
Reverse DNS (PTR records) is not automatic. Forward lookups working doesn't mean reverse lookups do too.
{% endhint %}
